# S3 / Object Storage aktivieren

PetKit-Kamera-Geräte (z.B. YumShare Dual, `deviceType 25`) fragen über
`dev_oss_sts_info_new_v2` kurzlebige Upload-Credentials an und laden danach
ihre Event-Bilder, Highlights, Time-Lapses und Video-Clips per HTTP PUT/GET
hoch. Localkit beantwortet diese Anfrage mit einer OCI-förmigen Antwort,
zeigt darin aber auf sich selbst zurück (`routes/web.php`, die
`ObjectStorageController`-Routen). Diese Emulation persistiert die Uploads
auf ein konfigurierbares Laravel-Filesystem-Disk — standardmäßig der im
`docker-compose.yml` mitgelieferte Garage-S3-Dienst (`localkit-storage`).

## Kurzfassung: Standard-Docker-Setup

Wenn du das mitgelieferte `docker-compose.yml` nutzt, ist der Garage-S3-Dienst
schon vorkonfiguriert — die Werte in `.env.example` passen zu den
Garage-Defaults im Compose-File. Es reicht in der Regel, **eine** Sache
anzupassen:

```env
LOCALKIT_STORAGE_ENDPOINT=http://<LAN-IP-dieses-Hosts>
```

Diese URL ruft die **Kamera** auf, nicht dein Browser — `127.0.0.1` oder
`localhost` funktioniert nur, wenn Kamera und Server dasselbe Gerät sind. In
der Praxis muss hier die LAN-IP des Docker-Hosts rein (z.B. `http://10.0.0.5`),
damit das Gerät die Emulation erreicht.

Alles andere kann unverändert aus `.env.example` übernommen werden.

## Benötigte Env-Variablen

| Variable | Default (`.env.example`) | Zweck |
|---|---|---|
| `LOCALKIT_STORAGE_ENABLE` | `true` | Schaltet die Storage-Emulation an/aus. `false` = Gerät bekommt eine leere Antwort und lädt nichts hoch. |
| `LOCALKIT_STORAGE_ENDPOINT` | `http://127.0.0.1` | Basis-URL, die das **Gerät** für Up-/Downloads nutzt — muss vom Kamera-LAN aus erreichbar sein. |
| `LOCALKIT_S3_ENDPOINT` | `http://localkit-storage:3900` | Wohin Laravel selbst spricht (Container-zu-Container im Docker-Netz). |
| `LOCALKIT_S3_REGION` | `garage` | S3-Region, wie sie der Garage-Client erwartet. |
| `LOCALKIT_S3_BUCKET` | `localkit` | Bucket-Name. |
| `LOCALKIT_S3_KEY` | (Garage-Default-Key aus `docker-compose.yml`) | S3 Access Key. |
| `LOCALKIT_S3_SECRET` | (Garage-Default-Secret aus `docker-compose.yml`) | S3 Secret Key. |

Diese landen über `config/filesystems.php` im Disk `localkit_storage`
(`s3`-Driver), welches wiederum in `config/localkit.php` unter
`storage.disk` referenziert wird.

## Weitere Optionen (`config/localkit.php`, meist Defaults lassen)

| Variable | Default | Zweck |
|---|---|---|
| `LOCALKIT_STORAGE_TYPE` | `oci` | Backend-Typ, den die Antwort dem Gerät meldet (kosmetisch, das Gerät spricht so oder so plain HTTP). |
| `LOCALKIT_STORAGE_NAMESPACE` | `localkit` | OCI-Namespace in der Antwort (kosmetisch). |
| `LOCALKIT_STORAGE_BUCKET` | `localkit` | OCI-Bucket-Name in der Antwort (kosmetisch, unabhängig von `LOCALKIT_S3_BUCKET`). |
| `LOCALKIT_STORAGE_AES_KEY` | `ea8e77e149818f72` | AES-128-Key (16 Zeichen), mit dem das Gerät Uploads verschlüsselt. Localkit speichert nur den Ciphertext, muss ihn nicht entschlüsseln. |
| `LOCALKIT_STORAGE_DEVICE_TYPE` | `25` | PetKit-Produkttyp, falls das Gerät selbst keinen numerischen Typ meldet. |
| `LOCALKIT_STORAGE_CYCLE_TTL` | `2592000` (30 Tage) | Gültigkeitsdauer der Storage-Credentials. |
| `LOCALKIT_STORAGE_PAR_TTL` | `43200` (12 Std.) | Gültigkeitsdauer der Pre-Authenticated-Request-URLs. |
| `LOCALKIT_STORAGE_DISK` | `localkit_storage` | Welches Laravel-Filesystem-Disk die Emulation tatsächlich beschreibt/liest. |

## Eigenen S3-Anbieter statt Garage nutzen

Statt des mitgelieferten Garage-Containers kannst du jeden S3-kompatiblen
Anbieter (AWS S3, MinIO, Cloudflare R2, ...) verwenden — einfach
`LOCALKIT_S3_*` auf dessen Zugangsdaten umbiegen:

```env
LOCALKIT_S3_DRIVER=s3
LOCALKIT_S3_ENDPOINT=https://dein-anbieter.example
LOCALKIT_S3_REGION=eu-central-1
LOCALKIT_S3_BUCKET=dein-bucket
LOCALKIT_S3_KEY=...
LOCALKIT_S3_SECRET=...
```

Wichtig: Die Kamera spricht weiterhin nur mit `LOCALKIT_STORAGE_ENDPOINT`
(Localkit selbst) — Laravel reicht die Objekte im Hintergrund an den
konfigurierten Disk durch. Der externe S3-Anbieter muss also nicht vom
Kamera-LAN aus erreichbar sein, nur vom Localkit-Server aus.

## Hinweis: separater `s3`/`AWS_*`-Block in `config/filesystems.php`

`config/filesystems.php` enthält zusätzlich einen Standard-Laravel-`s3`-Disk
(`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_BUCKET`, ...). Der ist
unbenutztes Laravel-Boilerplate und hat mit der Kamera-Storage-Emulation
nichts zu tun — für dieses Feature ausschließlich `LOCALKIT_S3_*` /
`LOCALKIT_STORAGE_*` setzen.

## Prüfen, ob es läuft

1. Docker-Stack starten, `localkit-storage` (Garage) muss laufen.
2. Ein Kamera-Gerät mit `debug_mode` aktivieren (Device-Formular) und die
   `dev_oss_sts_info_new_v2`-Antwort sowie nachfolgende PUT/GET-Requests in
   `storage/logs/device_{serial}.log` beobachten.
3. Erfolgreiche Uploads tauchen als Objekte im Garage-Bucket auf
   (`./s3/data` Volume) bzw. sind über die Snapshot-/Media-Anzeige im
   Geräte-Formular sichtbar.
